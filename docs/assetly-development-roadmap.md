# Assetly 개발 로드맵

이 문서는 Assetly를 어떤 순서로 개발할지 정리한다.

목표는 한 번에 완벽한 서비스를 만드는 것이 아니라, 실제로 동작하는 작은 버전을 빠르게 만든 뒤 점진적으로 확장하는 것이다.

## 1. 전체 단계

```text
Phase 0. 기획과 설계
Phase 1. 프로젝트 뼈대 생성
Phase 2. 인증과 조직
Phase 3. 자산 관리
Phase 4. QR과 변경 이력
Phase 5. 프론트엔드 앱 완성
Phase 6. 테스트와 품질 개선
Phase 7. 배포와 운영
Phase 8. v1.1 기능 확장
```

현재 상태(2026-10-02): Phase 0~4를 완료했고 Phase 5의 조직 전환·모바일 QR 흐름과 Phase 6의 핵심 Playwright 자동화를 완료했다.

## 2. Phase 0. 기획과 설계

목표:

- 만들 서비스의 범위와 구조를 확정한다.

산출물:

- 프로젝트 진행 가이드
- v1.0 제품 기획서
- 화면 흐름 문서
- DB 설계 문서
- API 명세 문서
- 아키텍처 문서

완료 기준:

- v1.0에서 만들 기능과 만들지 않을 기능이 구분되어 있다.
- 주요 화면이 정리되어 있다.
- 주요 테이블이 정리되어 있다.
- API 구조가 정리되어 있다.

## 3. Phase 1. 프로젝트 뼈대 생성

목표:

- 백엔드와 프론트엔드 개발을 시작할 수 있는 기본 구조를 만든다.

작업:

- Git 저장소 정리
- `backend/` Spring Boot 프로젝트 생성
- `frontend/` Next.js 프로젝트 생성
- `docs/` 문서 유지
- PostgreSQL Docker Compose 구성
- 환경변수 예시 파일 작성

완료 기준:

- 백엔드 서버가 실행된다.
- 프론트엔드 서버가 실행된다.
- PostgreSQL이 실행된다.
- 백엔드가 DB에 연결된다.

## 4. Phase 2. 인증과 조직

목표:

- 사용자가 가입하고 로그인한 뒤 조직을 생성할 수 있게 한다.

백엔드 작업:

- User 엔티티
- Organization 엔티티
- OrganizationMember 엔티티
- 회원가입 API
- 로그인 API
- JWT 발급
- 내 정보 조회 API
- 조직 생성 API
- 내 조직 목록 API
- 조직 권한 체크 기본 구조

프론트엔드 작업:

- 회원가입 화면
- 로그인 화면
- 조직 생성 화면
- 조직 선택/전환 기본 UI

완료 기준:

- 사용자가 회원가입할 수 있다.
- 로그인할 수 있다.
- 조직을 만들 수 있다.
- 조직 생성자는 Owner가 된다.
- 로그인 후 대시보드에 접근할 수 있다.

## 5. Phase 3. 자산 관리

목표:

- 조직 안에서 자산, 위치, 카테고리를 관리할 수 있게 한다.

백엔드 작업:

- Asset 엔티티
- Location 엔티티
- AssetCategory 엔티티
- 위치 CRUD API
- 카테고리 CRUD API
- 자산 CRUD API
- 자산 검색/필터 API

프론트엔드 작업:

- 대시보드 기본 화면
- 자산 목록
- 자산 등록
- 자산 상세
- 자산 수정
- 위치 관리
- 카테고리 관리

완료 기준:

- 조직에 위치를 등록할 수 있다.
- 조직에 카테고리를 등록할 수 있다.
- 자산을 등록할 수 있다.
- 자산 목록을 조회할 수 있다.
- 자산 상세를 조회할 수 있다.
- 자산 정보를 수정할 수 있다.

## 6. Phase 4. QR과 변경 이력

상태: 완료

목표:

- Assetly의 핵심 차별점인 QR 접근과 변경 이력을 구현한다.

백엔드 작업:

- Asset publicCode 생성
- publicCode 기반 자산 조회 API
- AssetHistory 엔티티
- 자산 생성 이력
- 자산 수정 이력
- 위치 변경 이력
- 상태 변경 이력
- 담당자 변경 이력

프론트엔드 작업:

- QR 접근 라우트
- 자산 상세의 QR 표시
- 변경 이력 목록
- 권한 없음 화면
- 로그인 후 원래 QR 페이지로 돌아가기

완료 기준:

- 자산별 QR 접근 URL이 있다.
- QR URL로 접근하면 로그인 후 자산 상세로 이동한다.
- 권한 없는 사용자는 자산 정보를 볼 수 없다.
- 자산 변경 시 이력이 남는다.
- 자산 상세에서 이력을 볼 수 있다.

## 7. Phase 5. 프론트엔드 앱 완성

상태: 진행 중 - 조직 전환과 모바일 공통 내비게이션 완료

목표:

- 실제 업무 프로그램처럼 사용할 수 있는 화면을 만든다.

작업:

- 앱 레이아웃 정리
- 사이드바
- 상단 조직 선택
- 로딩 상태
- 빈 상태
- 에러 상태
- 폼 검증
- 모바일 자산 상세 화면 개선
- QR 스캔 후 화면 개선

완료 기준:

- 로그인부터 자산 등록까지 막힘 없이 사용할 수 있다.
- 자산 상세 화면이 PC와 모바일에서 모두 읽기 쉽다.
- 오류가 발생해도 사용자가 상황을 이해할 수 있다.

## 8. Phase 6. 테스트와 품질 개선

상태: 진행 중 - 조직 전환, 로그인·로그아웃, QR 로그인 복귀와 모바일 자산 수정 자동화 완료

목표:

- 핵심 흐름이 깨지지 않도록 테스트를 추가한다.

백엔드 테스트:

- 회원가입
- 로그인
- 조직 생성
- 조직 권한 체크
- 자산 등록
- 자산 수정
- 변경 이력 생성
- 다른 조직 자산 접근 차단

프론트엔드 점검:

- 로그인 흐름
- 조직 생성 흐름
- 자산 등록 흐름
- QR 접근 흐름
- 권한 없음 흐름

완료 기준:

- 핵심 백엔드 테스트가 통과한다.
- 주요 사용자 흐름을 수동으로 검증했다.
- 권한 관련 버그가 없는지 확인했다.

## 9. Phase 7. 배포와 운영

목표:

- 실제 접속 가능한 환경에 배포한다.

작업:

- Dockerfile 작성
- Docker Compose 운영 구성
- Nginx 설정
- HTTPS 설정
- 운영 DB 설정
- GitHub Actions 테스트 자동화
- 배포 스크립트 작성
- 운영 환경변수 설정

완료 기준:

- 실제 도메인 또는 서버 주소로 접속할 수 있다.
- 회원가입, 로그인, 조직 생성, 자산 등록이 운영 환경에서 동작한다.
- HTTPS가 적용되어 있다.
- main 브랜치 기준 테스트가 자동 실행된다.

## 10. Phase 8. v1.1 기능 확장

v1.0이 안정화된 후 확장한다.

후보 기능:

- 이미지 업로드
- 점검 기록
- 대여/반납
- 이메일 초대
- Excel 내보내기
- QR 라벨 PDF 생성
- 이메일 알림
- 고급 검색

확장 기준:

- 실제 사용 흐름에서 필요성이 확인되었는가?
- 기존 구조를 망가뜨리지 않고 추가 가능한가?
- 포트폴리오 설명 가치가 있는가?

## 11. 우선순위 규칙

개발 중 기능 우선순위가 헷갈리면 다음 순서로 판단한다.

1. v1.0 핵심 흐름에 필요한가?
2. QR 기반 현장 관리 가치와 직접 연결되는가?
3. 멀티테넌트 SaaS 구조를 보여주는가?
4. 포트폴리오 설명 가치가 높은가?
5. 구현 비용이 MVP에 적절한가?

위 기준에 맞지 않으면 v1.1 이후로 미룬다.
