# Assetly 화면 흐름 설계

이 문서는 Assetly v1.0에서 사용자가 실제로 어떤 화면을 거쳐 서비스를 사용하는지 정리한다.

목표는 화면을 예쁘게 그리는 것이 아니라, 개발 전에 사용자 흐름과 필요한 화면을 명확히 정하는 것이다.

## 1. 전체 화면 목록

### 로그인 전

- 로그인
- 회원가입

### 온보딩

- 조직 생성
- 조직 선택

### 앱 메인

- 대시보드
- 자산 목록
- 자산 등록
- 자산 상세
- 자산 수정
- 위치 목록
- 위치 등록/수정
- 카테고리 목록
- 카테고리 등록/수정
- 멤버 목록
- 변경 이력
- 설정

### QR 접근

- QR 자산 접근
- 권한 없음
- 로그인 필요

## 2. 기본 레이아웃

로그인 후 화면은 업무용 웹 애플리케이션 형태로 구성한다.

### 좌측 사이드바

- Dashboard
- Assets
- Locations
- Categories
- Members
- History
- Settings

### 상단 영역

- 현재 조직명
- 조직 전환
- 사용자 메뉴
- 로그아웃

### 본문 영역

각 기능 화면이 표시된다.

모바일에서는 사이드바를 접고 하단 또는 상단 메뉴 형태로 전환할 수 있도록 고려한다. v1.0에서는 완벽한 모바일 앱 수준보다 QR 스캔 후 자산 상세 화면이 잘 보이는 것을 우선한다.

## 3. 로그인 전 흐름

### 3.1 회원가입

사용자는 이메일, 비밀번호, 이름을 입력해 가입한다.

입력 항목:

- 이름
- 이메일
- 비밀번호
- 비밀번호 확인

성공 시:

- 자동 로그인하거나 로그인 화면으로 이동한다.
- v1.0에서는 구현 단순화를 위해 회원가입 후 로그인 화면으로 이동한다.

실패 상황:

- 이미 가입된 이메일
- 비밀번호 형식 오류
- 필수 입력값 누락

### 3.2 로그인

사용자는 이메일과 비밀번호로 로그인한다.

성공 시:

- 사용자가 속한 조직이 있으면 대시보드로 이동한다.
- 속한 조직이 없으면 조직 생성 화면으로 이동한다.

실패 상황:

- 이메일 또는 비밀번호 불일치
- 비활성화된 계정

## 4. 온보딩 흐름

### 4.1 조직 생성

처음 가입한 사용자는 조직을 생성해야 한다.

입력 항목:

- 조직 이름
- 조직 설명

성공 시:

- 조직이 생성된다.
- 생성자는 Owner 역할을 가진다.
- 대시보드로 이동한다.

### 4.2 조직 선택

사용자가 여러 조직에 속한 경우 조직을 선택하거나 전환할 수 있다.

v1.0에서는 상단 조직명 클릭 시 소속 조직 목록을 보여주는 방식으로 처리한다.

## 5. 대시보드

대시보드는 현재 조직의 자산 현황을 빠르게 보여준다.

표시 정보:

- 전체 자산 수
- 사용 중 자산 수
- 보관 중 자산 수
- 수리 중 자산 수
- 최근 등록된 자산
- 최근 변경 이력

주요 액션:

- 자산 등록
- 자산 목록 보기
- 최근 변경 이력 상세 보기

## 6. 자산 목록

조직의 자산을 목록으로 보여준다.

표시 항목:

- 자산명
- 자산번호
- 카테고리
- 위치
- 상태
- 담당자
- 최근 수정일

기본 기능:

- 검색
- 상태 필터
- 카테고리 필터
- 위치 필터
- 자산 등록 버튼

v1.0 검색은 DB `LIKE` 기반 단순 검색으로 충분하다.

## 7. 자산 등록

관리자 또는 권한이 있는 사용자가 자산을 등록한다.

입력 항목:

- 자산명
- 자산번호
- 설명
- 카테고리
- 위치
- 상태
- 담당자
- 구매일
- 구매 가격

v1.0 상태 후보:

- AVAILABLE
- IN_USE
- REPAIR
- LOST

성공 시:

- 자산 상세 화면으로 이동한다.
- 자산 등록 이력이 생성된다.
- QR 코드 접근 URL이 생성된다.

## 8. 자산 상세

자산 상세 화면은 Assetly의 핵심 화면이다.

표시 정보:

- 자산명
- 자산번호
- 상태
- 카테고리
- 현재 위치
- 담당자
- 설명
- 구매일
- 구매 가격
- QR 코드
- 최근 변경 이력

주요 액션:

- 수정
- 위치 변경
- 상태 변경
- 담당자 변경
- 삭제
- QR 보기
- 변경 이력 전체 보기

권한에 따라 버튼 노출이 달라진다.

Member는 기본적으로 조회만 가능하다.
Manager 이상은 위치, 상태, 담당자 변경이 가능하다.
Admin 이상은 자산 정보 수정과 삭제가 가능하다.

## 9. 자산 수정

자산의 기본 정보를 수정한다.

수정 가능한 항목:

- 자산명
- 설명
- 카테고리
- 위치
- 상태
- 담당자
- 구매일
- 구매 가격

수정 성공 시:

- 변경 이력이 생성된다.
- 자산 상세 화면으로 돌아간다.

## 10. QR 스캔 흐름

QR 코드는 자산 상세 접근 URL을 가진다.

예시:

```text
https://assetly.example.com/a/IT-2026-00132
```

### 10.1 로그인된 사용자

1. QR을 스캔한다.
2. 자산 상세 페이지로 이동한다.
3. 서버는 자산번호로 자산을 찾는다.
4. 사용자가 해당 조직의 멤버인지 확인한다.
5. 권한에 맞는 상세 화면을 보여준다.

### 10.2 로그인되지 않은 사용자

1. QR을 스캔한다.
2. 로그인 화면으로 이동한다.
3. 로그인 성공 후 원래 접근하려던 자산 상세 화면으로 이동한다.

### 10.3 권한이 없는 사용자

1. QR을 스캔한다.
2. 서버는 자산을 찾는다.
3. 사용자가 해당 조직 멤버가 아니면 권한 없음 화면을 보여준다.

권한 없음 화면에는 자산 정보가 노출되지 않아야 한다.

## 11. 위치 관리

위치는 조직별로 관리한다.

표시 항목:

- 위치명
- 설명
- 등록일
- 해당 위치의 자산 수

기능:

- 위치 등록
- 위치 수정
- 위치 삭제

위치 삭제는 해당 위치에 자산이 없는 경우에만 허용한다.

## 12. 카테고리 관리

카테고리는 조직별로 관리한다.

표시 항목:

- 카테고리명
- 등록일
- 해당 카테고리의 자산 수

기능:

- 카테고리 등록
- 카테고리 수정
- 카테고리 삭제

카테고리 삭제는 해당 카테고리에 자산이 없는 경우에만 허용한다.

## 13. 멤버 관리

v1.0에서는 이메일 발송 초대 대신 이미 가입된 사용자를 이메일로 조직에 추가한다.

Owner와 Admin만 멤버 화면에 접근할 수 있다. Owner는 모든 역할을 관리하고, Admin은 Manager와 Member만 관리한다.

표시 항목:

- 이름
- 이메일
- 역할
- 가입일

기능:

- 이메일로 멤버 추가
- 역할 변경
- 멤버 제거

마지막 Owner의 역할 변경과 제거는 차단한다. 실제 이메일 초대와 가입 대기 상태는 v1.1 이후에 검토한다.

## 14. 변경 이력

변경 이력 화면은 조직 전체 이력을 보여준다.

표시 항목:

- 변경 일시
- 자산명
- 작업자
- 작업 종류
- 변경 전 값
- 변경 후 값
- 메모

필터:

- 자산
- 작업 종류
- 작업자
- 기간

v1.0에서는 필터를 최소화하고 최신순 목록부터 구현한다.

## 15. 설정

v1.0 설정 화면은 최소 기능만 제공한다.

표시 항목:

- 조직명
- 조직 설명
- 내 역할

Owner는 조직명과 설명을 수정할 수 있다.

| 화면/기능 | Owner | Admin | Manager | Member |

| 자산 등록 | 가능 | 가능 | 제한 | 불가 |

## 17. 프론트엔드 라우트 초안

```text
/login
/signup
/onboarding/organization
/app
/app/assets
/app/assets/new
/app/assets/:assetId
/app/assets/:assetId/edit
/app/locations
/app/categories
/app/members
/app/history
/app/settings
/a/:assetCode
```

`/a/:assetCode`는 QR 스캔 전용 공개 진입점이다. 실제 데이터 접근은 인증과 권한 검사를 거친 뒤 허용한다.

## 18. 다음 작업으로 넘길 결정 사항

DB 설계에서 다음 사항을 확정해야 한다.

- 자산번호를 조직 내 유니크로 둘지, 전체 서비스 유니크로 둘지
- QR 접근 경로에서 `assetCode`만 쓸지 별도 공개 토큰을 쓸지
- 자산 삭제를 물리 삭제로 할지 비활성화로 처리할지
- 멤버 초대를 v1.0에 포함할지 v1.1로 미룰지
